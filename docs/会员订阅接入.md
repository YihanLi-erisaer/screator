# 邮箱会员与订阅接入

桌面新增独立「会员订阅」页面，通过已有 Tauri → Python worker 管线调用会员后端。邮箱会员与 Bilibili／其他投稿平台授权分开，不替换任何原有平台凭据，不改变现有视频、素材或投稿流程。

## 服务地址

尚未提供生产域名，因此发布包不会默认连接一个虚构服务。启动应用前，由发行方或运维设置可信 API origin：

```bash
SCREATOR_MEMBERSHIP_API_URL=https://YOUR_API_HOST npm run desktop --prefix desktop
```

只能填写源地址，不能带 `/api/v1`、用户信息、路径、查询参数或 fragment。应用会自行附加 `/api/v1/`。生产要求 HTTPS；服务地址不会由 WebView 表单或其他页面任意修改。未配置或配置无效时，会员页显示明确引导，本地创作保持可用。

本地开发需额外显式打开 loopback HTTP：

```bash
SCREATOR_MEMBERSHIP_API_URL=http://127.0.0.1:8000 \
SCREATOR_MEMBERSHIP_ALLOW_LOOPBACK=true npm run desktop --prefix desktop
```

Windows PowerShell：

```powershell
$env:SCREATOR_MEMBERSHIP_API_URL = 'http://127.0.0.1:8000'
$env:SCREATOR_MEMBERSHIP_ALLOW_LOOPBACK = 'true'
cd desktop
npm run desktop
```

HTTP 只允许精确的 localhost、127.0.0.1 或 ::1，不能把此开发开关用于远程服务。安装版也从启动环境继承配置；例如 macOS 可在受控启动器中设置环境再启动 `.app/Contents/MacOS/screator`。桌面不会自动读取项目 `.env`。会员后端的部署、SMTP 与商户配置见 [screator-backend](https://github.com/YihanLi-erisaer/screator-backend) 文档。

## 用户流程

1. 注册邮箱与 12–128 字符密码，收到邮件后在后端自带页面确认邮箱，再回应用登录。找回密码也使用邮件页面，不在桌面缓存验证令牌。
2. 页面读取当前会员、六种套餐和真实可用支付渠道。Standard 月／季／年为 ¥19／¥49／¥188，Pro 为 ¥29／¥79／¥299；价格实际以服务器返回为准。
3. 阅读日历月周期与不同档位分别计时规则，选择渠道并确认购买。Stripe／支付宝通过本人订单回查和渠道域名白名单校验后，在系统浏览器打开；微信在本机将经过校验的 weixin URL 编成 PNG 二维码。
4. 页面每三秒查单，最长两分钟，页面隐藏／卸载时停止轮询。付款确认后刷新服务器会员状态；自动查询暂停后可手动刷新。扫码、支付返回页或关闭浏览器不会直接开通会员。
5. 网络中断时，从「待恢复的支付请求」恢复原请求；同一 UUID 不会产生重复订单。订单列表支持每页 20 笔。已过期订单不再显示可付款二维码，也不能打开收银台。

支付为单次购买，不自动续扣。1／3／12 个日历月分别为月／季／年；同档顺延，不同档独立计时，Pro 同时有效时优先，不折现、不暂停原订阅。退款／争议可撤销对应订单权益。具体 Standard／Pro 功能边界仍需业务定义，本次不擅自限制原本地功能。

## 凭据与故障恢复

访问令牌只在 Python 内存；刷新令牌只在系统 keyring，按规范化 origin 隔离。React／JSON Lines 响应不包含访问令牌、刷新令牌或原始支付 URL。系统浏览器入口只接受订单 ID，worker 先向后端获取本人订单、核对状态和渠道，再打开经过验证的链接；不会扩大 Tauri 的通用外链权限。

刷新在 RLock 内串行执行，避免同一 refresh token 并发重放。网络／503 不清除可恢复的刷新凭据；明确 401 撤销本地会话。keyring 写入／删除失败后，本进程停止自动使用旧凭据，修复系统存储后允许重新登录，不会被旧值永久阻挡。退出首先尽力撤销云端会话，再清除本地凭据；离线退出会明确说明云端撤销尚未完成。

`data/membership-pending.json` 只保存支付 UUID、origin、用户 UUID、套餐与渠道，不保存密码、令牌或支付链接。先用原有 atomic_json 原子落盘，再发下单 HTTP。成功响应后清理记录失败仍保留原幂等键，并展示已有订单；首次写入失败则不会发下单请求。损坏的恢复账本不会被静默覆盖。

网络／5xx 的订单结果仍不确定，不能随意移除恢复记录。明确 400／404／409 的请求会提供「移除恢复提示」，必须先确认；此操作只移除本机恢复提示，不取消云端订单、不退款，原订单仍须在列表核对，避免重复付款。

会员请求的错误映射为脱敏信息，不向 UI 回显原始响应、认证头或网络异常中的 URL。429 遵守 Retry-After，并在等待期间本地拒绝重复请求。

## 实现与验证

Python 客户端为 `screator/desktop_membership.py`，在 `DesktopService.dispatch` 注册 `membership.*` 白名单方法。主要方法为 status、login／logout、register／resend_verification／forgot_password、plans、providers、checkout／retry_checkout／dismiss_checkout、orders／order 和 open_checkout。verify_email／reset_password 也可供受控集成测试使用。

React 页面为 `desktop/src/MembershipPanel.tsx`，独立 lazy chunk，沿用原 zh-CN／zh-HK／en 目录流程。界面预览明确未配置，不模拟注册或支付成功。

```bash
python -m unittest tests.test_membership -v
cd desktop
npm run build
npm run test:e2e -- e2e/membership.spec.ts e2e/desktop.spec.ts e2e/localization.spec.ts
```

跨仓真实 HTTP／worker／浏览器验收脚本位于后端仓库，覆盖真实会员 API、数据库与签名回调。真实商户扣款、实际邮件投递、生产域名与安装包联调仍需商户／SMTP／部署配置；本地签名夹具不代表真实收款成功。
