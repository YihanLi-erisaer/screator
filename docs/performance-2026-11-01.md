# 性能检查与优化记录（2026-11-01）

本次检查覆盖 Python 任务列表查询、后台调度循环、React 任务/日志轮询，以及已有 worker 启动路径。已落实三项优化，集中减少重复数据库读取与空闲刷新。

## 改动

1. **列表关联数据批量读取**：每页任务、导入历史、投稿目标与执行记录分别批量加载。保持原来的排序、20 条分页、平台/账号筛选、投稿目标显示名称和 `run_id`。读取完成后释放数据库锁，再获取调度器快照，保持锁顺序。
2. **调度器空闲休眠**：没有活跃任务时等待显式信号，避免每 250 ms 扫描 SQLite 并广播 `queue.changed`。新任务、取消和关闭仍可唤醒；活跃任务和上传等待倒计时维持原刷新频率。
3. **可见窗口串行轮询**：任务与详情日志在窗口隐藏时停止轮询，恢复可见后立即刷新；慢请求完成后再安排下一次读取，避免日志请求积压。组件退出后丢弃未完成请求的结果。

## 本机测量

环境：Windows，Python 3.14.6，项目声明的依赖，独立 `build/perf-venv` 环境。原 `.desktop-venv` 指向已不存在的 Python 3.13，因此未用它执行测试，也未改动它。

运行 `python scripts/benchmark_task_lists.py --samples 9 --tasks 1000 10000`。每种规模包含等量的本地已完成任务与导入历史，页面大小为 20，预热后取 9 次中位数；测量时排除调度线程查询。固定历史日期为 2026-01-01，不包含真实账号、网络请求或上传。历史首屏主要是本地记录，不能将结果理解为纯导入页或真实平台耗时。

| 数据规模 / 查询 | 优化前 ms | 优化后 ms | SQL 次数（前 → 后） |
|---|---:|---:|---:|
| 1,000 本地任务 / 任务列表 | 31.956 | 3.774 | 105 → 8 |
| 10,000 本地任务 / 任务列表 | 38.811 | 5.702 | 105 → 8 |
| 1,000 本地 + 1,000 导入 / 投稿历史 | 38.557 | 8.640 | 107 → 10 |
| 10,000 本地 + 10,000 导入 / 投稿历史 | 114.337 | 73.435 | 107 → 10 |
| 10,000 本地 + 10,000 导入 / 历史文字搜索 | 196.706 | 181.531 | 107 → 10 |
| 10,000 本地任务 / Bilibili 平台筛选 | 50.888 | 16.898 | 105 → 8 |

10,000 条任务列表在该实验中耗时降低约 **85%**。这反映本机合成数据下的服务调用耗时，不代表应用整体 CPU 降低 85%。

调度器空闲观测窗口为 2 秒：`queue.changed` 从 7 次降到 0 次，相关 SQL 从 14 次降到 0 次。该计数只针对空闲调度循环，不包含前台主动读取。

优化后源码 worker 就绪时间的 5 次中位数为 897.54 ms；这是当前运行环境的测量，没有用于声明启动速度提升，也不是系统冷启动或安装包启动测试。

## 回归与复现

- 首轮 `python -m unittest discover -s tests -q`：运行 470 项，461 通过、8 跳过、1 失败（209.934 秒）。唯一失败为 `test_download_cancel_keeps_partial_and_stops_process` 对临时文件大小的断言。未修改的原始 HEAD `383c5bd` 在相同环境也出现相同失败。
- `python scripts/smoke_worker.py`：8 项协议响应及离线媒体处理烟测通过，无网络请求与投稿。
- `cd desktop` 后运行 `npm run build`：本地化目录校验、TypeScript 与 Vite 构建通过，保留已有的大于 500 kB 分包警告。
- `cd desktop` 后运行 `npm run test:e2e -- e2e/polling.spec.ts`：2 项通过，覆盖隐藏/恢复、在途请求恢复可见、慢请求串行与退出清理。另有 4 项关闭流程和 6 项任务分页/趋势/队列/筛选/详情交互通过，共 12 个不同 E2E 用例。
- 新增 `tests/test_scheduler_idle.py`：空闲零扫描、新任务唤醒、结束通知及上传倒计时。
- 扩展 `tests/test_startup.py`：查询数量不随页大小增长，并验证混合历史、投稿目标名称和缺失/空执行记录。

查询批量化的分页、筛选、历史与统计首轮回归 25 项通过；补充空执行记录兼容后，`test_startup` 的 7 项再次通过。调度器专门回归 2 项、关闭回归 10 项及桌面回归 44 项通过。以上脚本均可在正常配置的开发环境复现；具体耗时受机器负载和文件系统影响。

随后定位并修复了下载取消测试：yt-dlp 在缓冲写入后即可发送 progress，而当前 Python 的默认写缓冲为 128 KiB，原测试仅发送 16 KiB 就取消，不能保证文件已有内容。临时文件实验复现了写入 16 KiB 后文件大小仍为 0、刷新缓冲后才变为 16 KiB。测试现发送超过缓冲区的未完成响应，等到进度与非空临时文件都可观测后再取消，并验证已写入内容保留、未生成完整文件、无重试和旧文件未变。准备阶段断言失败时，也会先停止写入线程再清理临时目录。修改仅涉及测试，不增加下载器的强制刷新开销。

修复后的完整后端回归：**470 项，462 通过、8 跳过、0 失败**（258.892 秒）。下载取消模块的 4 项可运行测试通过、1 项 POSIX 专用测试在 Windows 跳过；补充异常清理后，该下载取消用例也单独复测通过。

## 仍然存在的性能边界

大规模历史文字搜索仍需扫描 Unicode 标题和导入 JSON，统计也需要遍历符合条件的历史。本次没有引入可能返回旧数据的缓存或更改数据库结构。任务列表和空闲调度的优化不改变下载网络速度、模型推理速度或平台上传限速。

本次验证针对本地源码与浏览器测试桥接；未重新打包、安装或验证真实平台投稿，也未提交或推送 Git 改动。
